### **10:05 – 10:15 AM | Step 0 — Let Codex Clone the Scaffold into Your Own Repo (10 min)**

Every participant uses Codex Desktop to clone the scaffold branch, detach it from the upstream, and push it as a new private GitHub repo under their own account. No manual `git` commands today — this is itself a Codex exercise.

Open Codex Desktop in an empty parent folder where you keep your projects (e.g. `~/projects`), confirm `gh` CLI is installed and signed in (`gh auth status`), then paste:

```text
Please set up a fresh copy of the WUC Learn training repo as my own private GitHub repository.

Before you start, run `gh auth status` and confirm I'm signed in to the GitHub CLI. If I'm not, stop and tell me to run `gh auth login` first.

Then, in the current directory:

1. Clone ONLY the scaffold branch — do not fetch the other branches:
   git clone --single-branch --branch 01-tcm-platform-scaffold https://github.com/jianwei0510/wuc-learn.git my-wuc-learn

2. cd into my-wuc-learn.

3. Detach from the upstream and rename the working branch to main:
   git remote remove origin
   git branch -M main

4. Create a new PRIVATE GitHub repo under my account called `my-wuc-learn`, set it as origin, and push:
   gh repo create my-wuc-learn --private --source=. --remote=origin --push

5. Run `npm install`.

6. Copy `.env.example` to `.env.local` (leave the values empty for now).

7. Print the URL of my new GitHub repo, confirm `npm run dev` is ready, and stop. Do not start the dev server yourself.

Do not fork the original repo. Do not pull branches 02 or 03 — those are answer branches I should not see yet.
```

Then start the dev server yourself:

```bash
cd my-wuc-learn
npm run dev
```

Verification:

- `http://localhost:3000` loads and shows the course list
- Course list is being read from `data/wuc-learn.db` (not hard-coded)
- No login button yet — expected at this stage
- Your new private repo is visible at `https://github.com/<your-username>/my-wuc-learn`

**Manual fallback (only if Codex or `gh` fails):**

```bash
git clone --single-branch --branch 01-tcm-platform-scaffold https://github.com/jianwei0510/wuc-learn.git my-wuc-learn
cd my-wuc-learn
git remote remove origin
git branch -M main
# Create an empty repo at https://github.com/new (do NOT add a README), then:
```

IT will circulate. If Node, npm, `gh` auth, or SQLite native build fails, fix it now before moving on.

### **10:15 – 10:35 AM | Step 1 — Clerk User Auth (20 min)**

Goal: signed-in users, with their basic info written to the local SQLite database.

**Part B — Let Codex wire it up (15 min):**

Switch to a working branch off scaffold, then paste this into Codex:

```text
Clerk has already been set up in this project.

Please help me connect Clerk login to this app, and add a simple database to save user information.

I want users to clearly see Sign in, Sign up, and their profile button after logging in.

When a user logs in, please save their basic user information in the database.

Also make sure course data is stored in the database instead of only being hard-coded in the app.

Please prepare the database structure we will need later for payment:

On the course page:
- If the user is not logged in, ask them to sign in before purchasing or unlocking the video.

Please finish the integration, test that it works, and tell me what changed.
```

Verification:

- Sign up with your `@wuc.edu` email, confirm you land back on the course list signed in

**Fallback:** if Codex is slow or stuck, `git checkout 02-tcm-platform-clerk-auth` and continue — you'll still learn Stripe in the next step.

### **10:35 – 10:55 AM | Step 2 — Stripe Payment Links (20 min)**

Goal: a signed-in user completes a Stripe test-mode purchase and the course unlocks.

**Part A — Stripe test-mode key (3 min):**

1. `https://dashboard.stripe.com` → toggle **Test mode** ON.
2. Developers → API keys → copy the **Secret key** (`sk_test_...`).
3. Add to `.env.local`:

```env
NEXT_PUBLIC_APP_URL=http://localhost:3000
STRIPE_SECRET_KEY=sk_test_...
```

**Part B — Let Codex build the flow (10 min):**

Paste into Codex:

```text
This project already has Clerk authentication, a local SQLite user database, and course data stored in the database.

Please add the simplest Stripe payment flow for a classroom demo.

Use Stripe Payment Links instead of requiring students to use the Stripe CLI.

Requirements:
- A signed-in user should be able to click Purchase on a course.
- The app should redirect to the Stripe Payment Link for that course.
- After payment, Stripe should redirect back to the app with a Checkout Session ID.
- The app should verify the Checkout Session on the server using the Stripe secret key.
- Only grant course access after verifying the payment status, amount, currency, course, and signed-in user.
- Store successful purchases in the database.
- Add a My courses page where users can see courses they already purchased.
- Store each course's Stripe Payment Link in the course database record, not in environment variables.
- Do not hard-code the instructor's Payment Link. Leave course Payment Links empty until each student creates their own Stripe Payment Link.

Please implement it, update README with the setup steps, and test that the app builds.
```

**Part C — Create your own Payment Links via Codex (5 min):**

This is the part participants always get wrong. **Three things must line up or payment looks successful but the course never unlocks:** redirect URL with `{CHECKOUT_SESSION_ID}` preserved literally, amount and currency matching `priceCents`, and a dev-server restart after writing the link into `lib/db.ts`.

Connect your Stripe account to Codex, confirm test mode, then run:

```text
Use my connected Stripe account in test mode only.

For each course in lib/db.ts courseSeed whose stripePaymentLinkUrl is still null:
- Create a Stripe product named after the course title.
- Create a one-time price in USD that exactly matches the course's priceCents (for example 4900 means $49.00 USD).
- Create a Stripe Payment Link for that price.
- Set the Payment Link's after-payment behavior to redirect to this exact URL, keeping {CHECKOUT_SESSION_ID} as a literal template token and using that course's own slug:
  http://localhost:3000/checkout/complete?courseSlug=<COURSE_SLUG>&session_id={CHECKOUT_SESSION_ID}
- Write the resulting Payment Link URL back into that course's stripePaymentLinkUrl in lib/db.ts.

Do not use live mode. Do not touch courses that already have a Payment Link.
After updating lib/db.ts, tell me to restart the dev server so the new links take effect.
```

Restart `npm run dev` after the file is updated.

**Part D — End-to-end test (2 min):**

- Click Purchase on a course
- Use test card `4242 4242 4242 4242`, any future expiry, any CVC, any ZIP
- Confirm you land back on `/checkout/complete` and the course unlocks
- Check `/my-courses` shows the purchased course

**Fallback:** if Stripe-via-Codex fails, create one Payment Link manually in the Stripe Dashboard for one course only, paste the URL into `lib/db.ts`, restart, and demo with that single course. `git checkout 03-tcm-platform-stripe-payment` is the last-resort fallback.
